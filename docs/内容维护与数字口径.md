# 内容维护与数字口径

站内的关键数字只维护一处，构建期自动核对。改数字前先看这份说明。

## 三个数据源

| 数字 | 唯一来源 | 谁在用 |
|---|---|---|
| 辅食起点 / 频次 / 质地推进 | `src/content/data/feeding.json` | /feeding 页面、部分月龄条目 |
| 跨主题通用数字（果汁上限、盐糖蜂蜜、屏幕、牙膏、睡眠总时长） | `src/content/data/facts.json` | 月龄条目、/sources「关键数字与口径」 |
| 六项 WHO 粗大运动窗口 | `src/content/data/milestones.yaml` 的 `windows` 字段 | /milestones 图表与逐条列表、月龄条目的「WHO 窗口」行 |

月龄分段在 `src/lib/stages.ts`，32 条预警征象在 `src/lib/warningSigns.ts`，二者也是单一来源。

## 改数字的流程

1. 只改上表对应的文件；
2. 跑 `npm run validate`（会执行 `validate-content.mjs` + `check-facts.mjs`）；
3. 如果文中还有旧值，校验会指出文件与冲突内容，按提示改掉；
4. 构建通过后再提交。

## 校验规则（check-facts.mjs）

| 规则 | 内容 | 失败方式 |
|---|---|---|
| F1 | 正文里的小数月龄区间（如 3.8～9.2）必须等于 `milestones.yaml` 的某个窗口 | 构建失败 |
| F2 | 提到加辅食时，「满 N 月龄」必须等于 `facts.feeding.startMonth` | 构建失败 |
| F3 | 提到果汁时，「N 毫升」必须等于 `facts.feeding.juiceMaxMl` | 构建失败 |
| F4 | 「N 岁前不加盐/糖/蜂蜜」必须是 1 岁 | 构建失败 |
| F5 | 正文写的睡眠总时长必须与 `facts.sleep` 对应阶段一致；未登记的阶段给警告 | 失败 / 警告 |
| F6 | 里程碑 YAML 的 `description` 不得再写窗口数字 | 构建失败 |

另有 `validate-content.mjs` 的 R10：条目 `window` 字段必须能在 `milestones.yaml` 的 `windows.key` 中找到。

## 条目如何引用窗口

在月龄条目 frontmatter 里写：

```yaml
window: "walk"   # 对应 milestones.yaml 中 windows[].key
```

构建时会在条目正文下方自动渲染一行「WHO 窗口：独走 8.2–17.6 个月（1～99 百分位）」，
所以**正文里不要再手写这组数字**。

可选 key：`sit`、`crawl`、`stand-support`、`walk-support`、`stand-alone`、`walk`。

## 新增数字时

- 跨条目的数字 → 加进 `facts.json`，并在 `check-facts.mjs` 里补一条正则规则；
- 只是一个页面自己的展示数字（如 /feeding 的频次）→ 放在对应 JSON，页面直接渲染；
- 不要在两处各写一遍再靠人工同步。
